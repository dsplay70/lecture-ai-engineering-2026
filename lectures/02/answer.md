知識を問う質問（セクション6）は、どちらの設定も同じ分類だった（最終課題の締切だけ asserted、教員名と次回のテーマは needs_review）。epochs=5 の答えは「FAQ には記載がありません。」で止まり、「運営に確認が必要です」まで書かない。

- 読み取れたこと：
  - **形式は5エポック（10ステップ）で学べた**。format_rate は5でも20でも1.000。JSON 1行とキー2つという「形」は、少ない学習で身につく
  - **中身（いつ確認に回すか、決まった文言）は学習が足りないと崩れる**。epochs=5 の失敗6問のうち5問は、`needs_review: true` に寄った側（根拠があるのに確認要求に逃げた2問、文言が足りない3問）。「記載がありません」という型だけを先に覚え、FAQにある質問まで確認に回している。loss が 1.58 と高いまま止まっていて、教師データの文を再現できていないことと合っている
  - **epochs=20 の失敗は、断定する側に寄った**。断定の失敗は epochs=20 で2問、epochs=5 で1問だった。学習を進めると確認に逃げる失敗は消えるが、FAQにない質問をFAQの項目で埋める断定は残る。学習量で直る失敗と直らない失敗がある
  - **時間は約1/4**（323秒 → 76秒）。ステップ数に比例している。今回の評価では、20エポックの方がよかった
  - Colab T4 と Mac の epochs=20 は、format_rate・content_rate・失敗した質問の2問が一致した。ただし「成績はいつ出ますか」の答えは、Colab が提出期限、Mac が提出形式を流用していて、中身は違った。READMEにあるとおり、同じ seed でも環境が違うと出力は完全には一致しない
- 制約：各設定1回ずつの実行。評価は21問だけで、1問で content_rate が約0.048動く。loss は10ステップごとの記録なので、epochs=5 は1点しかない。epochs=20 は loss 0.014 まで下がっていて、14件の教師データを覚え込んでいる（過学習）可能性があるが、今回の評価セットではその害（退行）は出ていない
- ファインチューニングが向く場面・向かない場面についての考察：
  - **向く**：出力の**形式や振る舞い**をそろえたいとき。今回、プロンプトで指示しても守れなかった JSON 形式が、14件・10ステップの学習で21/21守れるようになった。プロンプトに毎回長い指示を入れずに済むので、入力も短くできる
  - **向かない**：**知識を足したい、または「知らないことを知らないと言わせたい」とき**。FAQにない質問への断定は、学習量を4倍にしても直らず、似た項目の流用として残った。FAQの内容が変わるたびに学習し直す必要もある。知識はRAGのように入力で渡し、根拠がないときの扱いは評価セット（根拠なしの質問）で確かめる方がよい
  - **学習量にも注意が要る**：少なすぎると形式だけ身について中身が崩れ、多くすると断定の失敗が目立つようになった。エポック数は、loss だけでなく、失敗の型まで見て決める必要がある
