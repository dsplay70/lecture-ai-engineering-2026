実行環境：Mac のローカル（`uv sync --frozen`、Python 3.12）。第3回の開始時点のコード（`lec03-start` タグ）から `lec03` ブランチを作って実行した。モデルは既定の `gemini-3.5-flash-lite`。

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：質問は「AIE2026の講座の宿題にある「3レベル」とは何ですか？」
  - 第1回の `app.ask`：講座のことを知らないまま、「レベル1：基礎（必須）」「レベル2：応用」「レベル3：発展（チャレンジ）」と、一般論で**もっともらしい3段階を作って**答えた。2つ目の名前は「応用」で、用語集の「実装」と違う。最後に「講義のテキストやLMSで確認を」と付けている
  - エージェント：`search_glossary('3レベル')` で用語集を引き、「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、「どれか1つに取り組めば完了」と、`data/glossary.json` の `homework-levels` のとおりに答えた。最後に「関係する回：第1回」が付く
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` を1回
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring の「query には調べたい用語を1つだけ入れる」のとおり、用語を1つずつ検索した
- 1つの質問での LLM 呼び出し回数（`requests`）：どちらも **2回**（ツールを呼ぶかを決める1回と、結果を見て答える1回）。LoRAの質問はツールを2回呼んだが、2つの検索を1回の応答でまとめて呼んだので `requests=2`、`tool_calls=2`
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を `app/tools.py` に追加し、`app/agent.py` で登録した
  - docstring：「指定した回（1始まりの整数）の用語から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』のように、復習のための問題を求められたときに使う。返す answer は採点用の正解なので、利用者が答える前に見せない」
  - 用語集から指定の回の用語を `random.choice` で1つ選び、`{"question": "「○○」の意味は？", "answer": 定義, "lecture": N}` を返す。その回の用語がないとき（`lecture=0` など）は、`error` と、用語がある回の一覧を返す
  - 「第2回の内容から確認問題を1問出して」で、`make_quiz({'lecture': 2})` が1回呼ばれ、「『過学習』の意味は？」と出題された。docstring に書いたとおり、答えは出題の時点では見せなかった（`requests=2`）
  - 1回目の実行は 503（混雑）で失敗したので、取り直した

## 宿題

- 取り組んだレベル：**実装**
- やったこと：学習の記録を `learning_log/` に保存するツールを作り、保存の前に利用者の確認を挟んだ
  - `app/tools.py`：`save_learning_log(title: str, content: str)` を追加。`learning_log/<日時>_<題名>.md` に Markdown で保存する
    - 題名のうち、ファイル名に使えない文字や、フォルダの外を指す文字（`/` や `..`）は `_` に置き換え、必ず `learning_log/` の中に書くようにした
    - 題名か本文が空なら保存しない
  - `app/agent.py`：
    - `agent.tool_plain(tools.save_learning_log, requires_approval=True)` で登録し、`output_type=[str, DeferredToolRequests]` を加えた
    - `ask_approvals()` を追加：承認待ちの呼び出しごとに、ツール名と引数（題名と本文）を表示し、`この操作を実行してよいですか？ [y/N]` と聞く。`y` / `yes` 以外（空の入力、入力が無い場合を含む）は拒否にし、安全な側に倒した。拒否のときは `ToolDenied` に「保存せずに会話を続けてください」という理由を付けて、モデルに返す
    - `run_with_approval()` を追加：結果が `DeferredToolRequests` なら利用者に聞き、`DeferredToolResults` と `message_history=result.all_messages()` を渡して、もう一度 `run_sync` を実行する。CLI はこれを使う
    - 承認の前後で `run_sync` が2回に分かれるので、2回目に `usage=result.usage` を渡し、`[usage]` に合計の呼び出し回数が出るようにした（最初は2回目の分しか出ていなかった）
  - `tests/test_learning_log.py`：API キーを使わないテストを8件追加した。make_quiz、保存の中身、フォルダの外に書かない、空なら保存しない、承認待ちで止まって書かない、拒否なら書かない、承認なら書く、を確かめる。`uv run pytest -q` で全19件が通る
  - `learning_log/` は `.gitignore` に入っていて、保存した記録は commit されない
- 結果：
  - 依頼「LoRAとQLoRAの違いを用語集で確認して、今日の学習の記録として保存して」
  - **拒否（n）**：`search_glossary` を2回呼んだあと `save_learning_log` が呼ばれ、実行は承認待ちで止まった。題名「LoRAとQLoRAの違い」と、まとめた本文が表示された。`n` で拒否すると、ファイルは作られず、モデルは「保存の操作がキャンセルされたため保存は行っておりません」と答えた
  - **承認（y）**：同じく承認待ちになり、`y` で承認すると `learning_log/2026-11-23_152340_LoRAとQLoRAの違いについて.md` が作られた。モデルは「保存いたしました」と答えた。`requests=3`（検索を呼ぶ・保存を呼ぶ・最終回答）
  - **保存を頼まない質問**（「LoRAとQLoRAの違いを用語集で確認して」）：`save_learning_log` は呼ばれなかった
  - **docstring の一文で、ツールが呼ばれる割合が変わった**：

| docstring の最後の一文 | 同じ依頼を10回実行して、`save_learning_log` が呼ばれた回数 |
|---|---|
| 変更前：「ファイルを書き込む操作なので、実行前に利用者の承認が必要。」 | **8/10**（残りの2回は、ツールを呼ばずに、文章で「保存してもよろしいでしょうか？」と聞き返した） |
| 変更後：「保存してよいかの確認はアプリが利用者に行うので、保存を頼まれたら会話の中で確認を取らず、そのままこのツールを呼ぶこと。」 | **10/10** |

  - 聞き返した2回のうち1回は「ファイルを書き込む操作になるため、…承認をいただけますでしょうか？」と、docstring の言葉をそのままなぞっていた。もう1回も「念のため事前に利用者の皆様の承認をお願いしております」と、承認を理由にしていた。承認は `requires_approval=True` の仕組みが行うのに、docstring にも「承認が必要」と書いたため、モデルが自分でも先に確認を取ろうとしたと考えられる。聞き返されると、利用者は「はい」と答えてもう1往復しないと保存できず、そのあと仕組みの承認の確認がもう一度出ることになる
  - 制約：各条件10回で、差は2回。偶然の範囲かもしれない。聞き返した2回は、たまたまどちらも標準入力に `y` を渡した回だったが、標準入力はモデルの入力には入らないので、関係はない
- 気づき・疑問：
  - 「取り消しにくい操作の前に確認する」ことは、指示文に書いてモデルに頼むより、`requires_approval=True` のように仕組みで止める方が確実だった。拒否すると、ツールは本当に実行されない
  - 一方で、仕組みで止めることを docstring にも書くと、モデルがそれを自分への指示と読み、会話の中で二重に確認しようとした。docstring には「モデルが何をすべきか」を書き、仕組みが受け持つことはモデルにやらせない書き方が要る
  - 承認の画面では、モデルが作った本文をそのまま見せている。本文は用語集の定義を言い換えたものだが、モデルが要約しているので、用語集と細部が違うことがある（例：「学習パラメータや保存ファイルサイズを大幅に削減」は用語集の「学習するパラメータが少なく」より強い言い方）。承認するときは、保存するかどうかだけでなく、中身が正しいかも人が見る必要がある
  - 疑問：Web版や複数人で使う場合、承認待ちの状態（`message_history` と承認待ちの呼び出し）をどこに持っておくのがよいか
- AIツールの利用：実装・実行・集計に Claude Code を使った。数字と出力は、手元で実行した `--trace` の結果から取った
